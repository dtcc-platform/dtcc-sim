# Run a Helmholtz simulation

Run commands from the checkout root. Use Python 3.12 and complex PETSc with
DOLFINx 0.11.0. Keep this environment separate from the one used for heat/wind.

## 1. Install and check the runtime

For the tested Linux x86-64 setup, use the [pinned installer](helmholtz-reproducible-install.md).
It builds the pinned Core revision with tagged boundary persistence for DTCC exports.
Replace the two example paths below with your Conda executable and a new
installation directory outside this checkout:

```bash
python3 tools/install_helmholtz.py --conda /path/to/conda --work-dir /path/to/new-installation --verify --detach
```

Wait for `exit-code.txt` in that installation directory to contain `0`; inspect
`status.json` and the phase logs if it fails. Then activate the installed prefix:

```bash
conda activate /path/to/new-installation/env
python -m dtcc_sim.helmholtz.check_runtime --workers 2 --mesh-generation
```

For a self-contained solver and plot, run the [visual box demo](helmholtz-visual-demo.md).
For a city workflow, start with the [small generated-mesh example](../demos/HELMHOLTZ_SMALL.md).
It needs no separately supplied thesis mesh and uses two workers. The reference
configurations below use sixteen workers and require the specified inputs.

### Alternative environment setup

The general setup below resolves the scientific dependencies rather than
reconstructing the pinned runtime. It installs the same Core revision declared
by Sim. See the [installation notes](helmholtz-installation-validation.md) for
the VTK packaging requirements. The pinned recipe is Linux-specific;
other platforms have not been validated by that recipe.

```bash
conda env create -f environment-helmholtz.yml
conda activate dtcc-helmholtz
uv pip install --python "$CONDA_PREFIX/bin/python" -e ".[helmholtz,helmholtz-mesh]"
python -m dtcc_sim.helmholtz.check_runtime --workers 16 --mesh-generation
```

For existing XDMF meshes only, install `.[helmholtz]` and omit
`--mesh-generation`. Installation can compile native dependencies. The readiness
check imports libraries and inspects runtime settings; it does not run a solve
or prove that a particular case fits in memory. Activate the environment in
later shells and use `python`, rather than `uv run` or `mpirun`.

## 2. Select a mesh and preview the run

For the reference box, supply the original h=4 m mesh and its HDF5 companion as:

```text
meshes/helmholtz/box-h4/volume_mesh_gbg.xdmf
meshes/helmholtz/box-h4/volume_mesh_gbg.h5
```

Meshes are supplied separately and excluded from Git. Inspect
[`helmholtz_box_10hz_h4.json`](../demos/configs/helmholtz_box_10hz_h4.json), then:

```bash
python -m dtcc_sim.helmholtz.launch --config demos/configs/helmholtz_box_10hz_h4.json
```

This prints the plan without building a mesh or running the solver. The config
sets 10 Hz, rho=1.10, 16 subdomains, 16 patch workers and one numerical thread
per worker, with the reference ARPACK controls. One Python process starts the
patch workers; do not start 16 MPI ranks.

For a city generated by DTCC, use
[`helmholtz_city.json`](../demos/configs/helmholtz_city.json) instead. Set its
bounds, `mesh_parameters.h`, mesh-cache directory and fresh output directory.
The full meshing request selects an intact cached mesh or generates a new one.
To prepare only the city mesh, without solving:

```bash
python -m dtcc_sim.helmholtz.launch --config demos/configs/helmholtz_city.json --mesh-only
```

JSON paths resolve relative to the JSON file. For an existing mesh, `mesh_h`
records its declared resolution; changing this label does not remesh the file.
For generation, h is a target maximum mesh size, not an exact edge-length
promise. Keep mesh-cache and result folders separate.

For the verified thesis-city configuration, use
[`helmholtz_thesis_city_h5.json`](../demos/configs/helmholtz_thesis_city_h5.json).
It explicitly selects `pou_mode: "geometric_hats"` and rho-threshold modes.
Supply the exact original mesh at its configured path. Reproducing an archived
case also requires compatible partitioner builds, eigensolver settings and
runtime; this JSON alone does not pin those libraries. The other examples keep
`pou_mode: "core_overlap_ramp"`. Both choices and cache rules are described in
[the weight reference](helmholtz.md#partition-of-unity-weights).

## 3. Run and inspect the result

Choose a new `output_dir` for every run. Existing cases are never overwritten.
For a foreground run with VTU export:

```bash
python -m dtcc_sim.helmholtz.launch --config demos/configs/helmholtz_box_10hz_h4.json --run --export vtu
```

On Linux, the detached launcher survives ordinary SSH disconnection:

```bash
bash demos/run_helmholtz_detached.sh demos/configs/helmholtz_box_10hz_h4.json
```

Retain the printed log-directory path. It contains `run.log`, `pid` and, after
exit, `exit-code.txt`. A zero exit code indicates convergence and successful
export. There is no numerical checkpoint/resume after process termination or a
reboot; use a fresh case directory for another attempt.

The configured case directory contains `prepared.json`, `mesh_provenance.json`,
`diagnostics.json`, solution/history files and `helmholtz.vtu`. Check convergence,
iteration count and `relative_residual` in `diagnostics.json`; the true residual
is distinct from GMRES's transformed-system stopping criterion. Open VTU in
ParaView, selecting `helmholtz_real`, `helmholtz_imaginary` or
`helmholtz_amplitude`. Amplitude is not a sound-pressure level.

## Python and saved results

Use [`HelmholtzWorkflow`](../dtcc_sim/helmholtz/workflow.py) for local preparation
and solving. Pass `params=HelmholtzParameters(...)` and call `.simulate()` to
receive a DTCC `VolumeMesh` with solution fields. `.result` and `.diagnostics`
retain the numerical result and convergence details. `.prepare()`, `.solve()`
and `.run()` remain available for advanced workflows, and `parameters=` remains
a supported alias. The registered `datasets.helmholtz_simulation` also accepts explicit
h, a fresh output folder and either an existing mesh or generation settings.
See the [API reference](helmholtz.md#registered-dtcc-dataset) for a complete call.
For supplied local meshes, omit `mesh_crs`; supply it only when the CRS is known.
Generated city meshes use EPSG:3006. No coordinate reprojection is performed.

A completed low-level case can be loaded/exported without solving again:

```python
from dtcc_sim.helmholtz import HelmholtzResult

result = HelmholtzResult.load("results/helmholtz/box-f10-h4-rho1p10-001")
print(result.converged, result.iterations, result.relative_residual)
result.save_dtcc("results/helmholtz/box-f10-h4-rho1p10-001/field.dtcc")
```

Standalone VTU/DTCC outputs carry mesh fields. For a dataset result, request
`format="dtccpkg"` to retain run provenance too. Input mesh/runtime identity is
checked before export; keep the original mesh and case manifest available.

The original source-placement and boundary rules are preserved. An exterior
Gaussian centre warns without moving the source. The reference box uses marker
-2 on all six exterior faces, including the bottom. Ordinary ARPACK runs may
vary with initialization; [controlled comparison evidence](helmholtz-review.md)
is scoped to its recorded case and runtime. Queued HTTP/Celery execution and
service deployment are outside this contribution.

For a small generated-mesh example with commands and recorded expected results,
see [the small example](../demos/HELMHOLTZ_SMALL.md).
